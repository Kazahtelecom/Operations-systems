Отчет по эксперименту с планировщиком CPU (HW06)
1. Гипотеза В данном эксперименте проверяется работа планировщика задач Linux (CFS)
 при конкуренции за ресурсы центрального процессора.
 Я предполагаю, что процесс с отрицательным значением любезности
 (nice -10) получит больше времени CPU по сравнению с процессом, имеющим положительное значение
 (nice 10), и завершится быстрее.  
2. Результаты эксперимента
Для создания условий конкуренции была запущена фоновая нагрузка из 3-х процессов dd.
 Результаты замера времени выполнения основной задачи
(count=2000):  Параметр

3. Анализ и выводы
Эксперимент подтвердил гипотезу: высокоприоритетный процесс выполнился быстрее на 0.258 секунды.
 Это происходит потому, что современный планировщик Linux — CFS (Completely Fair Scheduler) 
распределяет время процессора на основе весов.
 Процесс с nice -10 имеет гораздо больший вес, чем процесс с nice 10.
 В результате его виртуальное время (vruntime) накапливается медленнее, и ядро реже прерывает его работу 
в пользу других задач.
 Значения sys почти равны real, так как основная работа выполнялась на уровне ядра при копировании данных.  
4. Контрольный вопросЧто произойдет, если убрать фоновую нагрузку?
Если запустить тесты на пустой системе, разница во времени выполнения станет практически нулевой.
 Без борьбы за ресурсы планировщику не нужно ограничивать процессы по времени, 
и оба они смогут использовать доступные ядра CPU на полную мощность одновременно.
